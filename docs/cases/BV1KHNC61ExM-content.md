2. 验证 Agent 能否分段读取长视频，形成可追溯且与载体无关的 content map；

4. 验证成品、忠实度审计和最终交付门能否完整闭环；
5. 用真实运行发现单元测试未覆盖的契约问题。

核心语义不是“某枚火箭参数如何”，而是：创新依赖资本、人才、技术、产业链与数据积累；
可见的“0到1”更接近长期积累后的“0.9到1.0”，工程化与商业化本身也属于创新。

content map 同时保留了几个容易在摘要中丢失的边界：

- 讲述者自称不是火箭专家；
- 视频不是在否认差距或贬低 SpaceX；
- 资本不是创新的充分条件；
- 人才激励、知识产权保护等制度条件仍然重要；
- 视频中的合同金额、组织规模、供应商与行业数据尚未在本次转换中外部核验；
- OCR/ASR 对火箭型号和“韬（τ）定律”等专名存在冲突，相关旁例不作为成品论证支点。

## 媒介选择

媒介计划将论证深度和上下文依赖都评为 `high`，视觉潜力为 `medium`，最终选择
`article`，拒绝一图流、卡片组和 brief。

原因不是文章更“高级”，而是这个内容需要连续保留：

```text
争议框架
-> 五种积累
-> SpaceX 例证及其限定
-> 中国产业链例证
-> 对“0到1”的重新定义
```

把五种积累放进单页很容易，但会把相互依赖的论证变成五个并列口号，也难以同时放入
对 SpaceX 的肯定、对现实差距的承认和事实核验边界。因此真实路由证明了 Skill 没有把
“一图流更容易传播”当作默认答案。

## 真实运行发现的问题

第一次 `content-validate` 返回 `ready_for_delivery=true`，但没有把
`pass_with_warnings` 的披露要求放入 `warnings`。这意味着只读取最终校验结果的 Agent
可能漏报审计边界。

校验器随后增加 `FIDELITY_AUDIT_WARNINGS`：成品仍可交付，但调用方必须读取并披露当前
audit。该行为已补充回归测试。

## 结论

这条真实链路证明第一版不是只有 Schema：

```text
真实 OCR/ASR 证据
-> 分段语义重建
-> 内容结构驱动的媒介选择
-> Markdown 成品
-> 逐项忠实度审计
-> 可交付校验
```

当前尚未验证一图流渲染，也没有外部事实核验。下一轮应选择一个低上下文、高视觉潜力的
视频，验证 `one_page + SVG/HTML` 路径，而不是强行把本案例改成一图流。

## 这次要验证什么

本轮字幕和内容重构已经完成，真正暴露问题的是最后一公里：本地图片无法跟随富文本复制进入
公众号编辑器，因此文章必须保留人工插图位置。第一版虽然满足了可追踪性，却把机器需要的
信息全部堆进了人类界面。

第一版每张图包含：

- 虚线边框与浅色背景；
- 图片语义标题；
- 本地文件路径；
- “请手动插入”说明；
- 另一行“插入后删除占位区域”提示。

用户实际编辑后反馈，这样的插槽删除起来太麻烦，只需要预留位置并写图片地址。

## 从复杂占位收敛到最小交接

最终默认标记只保留一个人类可见元素：

```html
<p data-local-image-slot="assets/01-mission.jpg"
   style="margin:30px 8px;font-size:12px;color:#AAAAAA;text-align:center;">
  <span leaf="">assets/01-mission.jpg</span>
</p>
```

这个元素同时承担两个职责：

1. 上下 margin 为人工插图保留位置；
2. 相对路径告诉编辑者应该插入哪个文件。

插图以后只需删除这一行。`data-local-image-slot` 继续为 Agent 提供机器校验，但不增加
人类可见说明。绝对机器路径不进入公开交付物。

描述型插槽没有被彻底禁止，但改成按需能力：只有用户主动要求编辑指导，或文件名确实无法
辨认时才启用。通常情况下，详细说明放进清单也不如给文件起一个清楚的名字有效。

## 清单与预览同步简化

图片清单只说明一次人工边界，然后按文章顺序列相对路径，不再为每张图重复写位置、内容、
插入方式和删除方式。

预览按钮仍使用“复制排版正文”。成功提示明确说明复制内容不含本地图片，但操作指令同步
收敛为：“按路径插入图片，再删除路径那一行。”

## 机器验证与版本边界

最终 clean HTML 的确定性检查结果：

- 7 个 `data-local-image-slot` 与 7 个正文路径一一对应；
- 所有路径对应的本地文件均存在；
- 旧虚线卡片、图片说明和重复删除提示为 0；
- 本地 `<img>` 引用为 0；
- 正文下划线标记为 0；
- 公众号 HTML 校验器为 0 error、0 warning。

这次只改变图片交付方式，没有改变文章语义，因此内容工程版本保持清晰：

```text
content map: cmap-002       不变
media plan: mplan-002       不变
deliverable: dlv-001 -> dlv-002
fidelity audit: audit-001 -> audit-002
final validation: valid=true, ready_for_delivery=true
```

排版或交接变化需要新的 deliverable 与 audit revision，但不应重新生成字幕证据、内容地图或
媒介计划。

## 沉淀出的默认规则

公众号复制型 HTML 的本地图片交接默认采用：

```text
人类可见：一行相对图片路径
机器可见：data-local-image-slot
空间预留：同一元素的 margin
人工操作：插入图片后删除一行
详细说明：仅在用户要求或文件名歧义时启用
```

最重要的经验不是“占位组件应该长什么样”，而是：机器验证信息与人类编辑界面必须分离。
交付物要优化用户下一步真实要做的事情，而不是让预览状态看起来更完整。

## 这次新增验证什么

上一份草稿交接案例已经证明，临时 Base64 富文本可以把本地图片一次带进公众号。这次继续
验证四个更容易被“看起来成功”掩盖的问题：

1. 来源作者口吻是否会让 Agent 不自觉补写合理但没有证据绑定的事实；
2. 第三方排版器生成的文章包是否能在进入浏览器前做确定性检查；
3. 微信页面存在隐藏字段和辅助图片节点时，Agent 是否仍能读到真实可见状态；
4. 封面选择和草稿保存是否形成可复核的完整后置条件，而不是只相信一次点击或提示。

## 作者口吻不等于事实授权

`dlv-001` 初稿里有三类句子读起来顺畅，也符合常识，但没有被当前 content map 直接授权：

- 把 SpaceX 写成已经完成“大量”海上回收；
- 把专用平台的代价概括成“前期设计更重”；
- 把箭体每减少一公斤直接写成更高运载能力或更大任务余量。

审计没有因为正文采用作者口吻就放行这些句子，而是生成 `dlv-002`：删除无证据的数量化描述，
把“前期设计更重”改为设计从一开始围绕同一任务，并把减重收益收紧为片中明确讨论的箭体减重
空间与平台可维护性。

因此固化的规则是：`source_author` 只决定谁在说话，不决定什么可以当成事实。每个读者可能
当成事实的句子，仍需映射到 claim、caveat，或明确登记的 Agent inference。

这证明七个 `data-local-image-slot`、七条正文相对路径、七个清单条目和七个本地文件按顺序

互动 CTA 或“可直接粘贴”文案。它不判断文章观点是否正确，语义仍由 fidelity audit 负责。

## 不要统计页面里的全部图片节点

临时富文本一次粘贴后，微信把七张正文图片上传到自己的 CDN。本次页面 DOM 一度出现 14 个
`img` 节点：七个是可见、已加载且地址为 `mmbiz.qpic.cn` 的正文图片，另外七个是空地址、
零尺寸的辅助节点。

如果脚本只执行“统计所有 `<img>`”，会错误报告 14 张；如果只拿第一个匹配字段，也可能读到
隐藏标题、非活动封面菜单或重复原创控件。本次实际验收只统计满足以下条件的正文图片：

- 当前可见且有实际尺寸；
- 地址非空并已经完成加载；
- 解析后的当前地址由微信托管；
- 不是隐藏、零尺寸或编辑器辅助节点。

最终验收为七张正文图片全部可见、全部使用微信 CDN，`data:`、`file:`、`blob:`、`assets/...`
和正文路径文字均为零。14 这个数字只是 2026-08-09 页面版本的观察，不是 Skill 契约；长期
契约是上面的可观察后置条件。

## 封面与保存都需要完整收据

封面没有停在“点过从正文选择”。本次继续确认：

1. 选中指定的正文第一张原视频封面；
2. 完成裁剪确认；
3. 页面出现可见封面预览；
4. 预览使用微信托管地址；
5. 原来的空封面占位状态消失。

作者栏保持为空，原创声明保持未选择。草稿保存后，编辑页面得到稳定文章标识，历史版本出现
新的手动保存记录；再次读回时，标题、摘要、正文、七张图片和封面仍然完整。案例不保存具体
编辑 URL、内部标识值或 URL token。

本次只保存了草稿，没有发表、定时、群发、声明原创或修改账号设置。稳定文章标识和历史记录
属于平台收据，不能反向把内容审计 warning 改成 `pass`。

## 沉淀后的分层

```text
语义层：content map -> media plan -> source-author draft -> fidelity audit
包校验：marker/file/checklist -> clean/preview boundary -> deterministic JSON
运输层：临时 Base64 rich HTML -> 整篇一次粘贴 -> 微信 CDN 接管
页面验收：可见可加载图片 -> 元数据 -> 封面完整后置条件 -> 持久保存收据
```

固定的是授权、证据映射和后置条件，不是当前页面选择器、坐标、内部 URL 或辅助节点数量。
案例不保存 Cookie、Token、密码、剪贴板 Base64 或浏览器存储数据。

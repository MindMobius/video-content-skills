## 测试目的

1. 验证短链接能否取得平台字幕和硬字幕 OCR 两路独立证据；
2. 验证 Agent 能否按信息关系重构文章，而不是把字幕换成段落；
3. 验证正文能否保留来源作者的直接、冷静、带判断的口吻；
4. 验证可选公众号排版 Skill 只改变呈现，不引入营销话术或虚构作者；
5. 验证原视频封面在不上传图床的情况下，能以本地文件、可见插槽和导入清单完成交接；
6. 验证 HTML 合规检查与语义忠实度审计可以分别闭环。

成品标题为《你多付的三块钱，买了一个法律不存在的东西》。正文不使用“这个视频认为”

第一次 HTML 修订仍残留“原视频称”“原视频以”两处包装。它们没有被降级为警告，而是
修正后另存 `dlv-002`。正文前的来源说明可以出现“原视频标题”等 provenance 文案，因为
它与作者论证在视觉和语义上分离；审计正文时必须排除这块说明后单独扫描。

公开交付的顺序为：

1. 原视频封面的可见本地插入槽；
2. UP 主、原标题、规范链接、转录与重组方式、可能偏差及未站外核验声明；
3. 作者直接口吻的文章正文。

来源说明没有暗示 UP 主认可本次改编，也没有用免责话术掩盖新增观点。

## 可选排版 Skill 与交付包

文章语义稿稳定后，使用
[`isjiamu/gzh-design-skill`](https://github.com/isjiamu/gzh-design-skill) 的
`graphite-minimal` 主题生成微信公众号正文片段。该 Skill 只负责组件、内联样式、
`span leaf`、校验和预览外壳；内容地图、口吻、来源说明和审计仍由本项目控制。
本次验证使用 commit `ba1f4175519b481cb3566616c9e5178705067904`；标准安装器
`skills@1.5.22` 的 `--list` 模式可以发现名为 `gzh-design` 的 Skill。该记录只说明本次
集成基线，不把第三方仓库升级为项目运行依赖。

主题默认包含作者签名和互动 CTA，但本次目标是忠实传递信息，用户也明确反感流水线式
公众号文风，因此没有加入虚构署名、“点赞、在看、转发”、二维码或关注提示。排版默认值
不是内容授权。

最终本地包包含：

```text
wechat-article/
├─ article.md
├─ 你多付的三块钱买了一个法律不存在的东西_排版_石墨极简(graphite-minimal).html
├─ 你多付的三块钱买了一个法律不存在的东西_排版_石墨极简(graphite-minimal)_预览.html
```

干净 HTML 不包含 `file:`、`data:`、`blob:` 或本地相对路径图片，也没有把封面做成无法随

正文后在该位置上传封面，再删除插槽。

> 后续演进（2026-08-08）：这段保留的是当时真实使用的灰色虚线插槽。后续公众号编辑反馈
> 证明，边框、说明和删除提示会增加人工清理成本。当前默认协议已收敛为一行相对图片路径，
> 机器追踪放进 `data-local-image-slot`，插图后只删除路径行；描述型插槽改为用户主动选择。

预览按钮使用“复制排版正文”，成功提示明确写出“已复制排版正文，粘贴后请按图片清单

## 结论

这次真实运行证明公众号文章链路可以保持 Agent-first：

```text
平台字幕 + 硬字幕 OCR
-> 内容地图与载体计划
-> 作者口吻文章语义稿
-> 可选排版 Skill
-> 干净 HTML / 预览 / 本地素材清单
-> HTML 合规检查 + 忠实度审计
-> 可交付，不代替用户发布
```

最重要的沉淀不是一个固定模板，而是职责分层：Agent 决定内容，渲染器决定呈现，确定性
工具检查格式，审计检查语义，人只在本地图片导入和平台发布边界接手。

# 来源忠实的视频书面化设计

- 日期：2026-08-22
- 状态：已批准
- 分支：`codex/source-faithful-adaptation`

## 1. 背景与问题

`video-to-content` 当前强调“设计载体结构”和“组织内容”，但没有明确限制 Agent 的编辑权。实际生成的微信公众号文章因此容易走向两个极端：一种像信息摘要，另一种为了通俗、故事性或平台传播效果而重新提炼主题、增加比喻、改变叙事顺序，最终覆盖视频创作者已经完成的专业表达。

这不是排版问题，也不需要一套公众号文风系统。视频创作者已经决定选题、论证、案例、术语、节奏和语气；默认转换的目标应是把这些内容高保真地迁移到书面载体，而不是让 Agent 代笔重写。

## 2. 核心原则

> 默认把视频恢复成适合阅读的书面版本，而不是用另一个作者的声音重写视频。

视频是什么类型和气质，文章就保留什么类型和气质：专业内容保持专业，幽默内容保留原有幽默，克制内容不额外煽情。通俗易懂来自清晰的断句、指代、结构和解释，不来自降低专业密度或增加生活化比喻。

深度压缩、受众改写、模仿特定作者、增加新观点或重新建立叙事主线，只能在用户明确要求时进行。

## 3. 选择的方案

### 3.1 拒绝：一句“保留原风格”的提示词

单句约束不足以阻止 Agent 在长文中重新提炼主题或增加解释，缺少可审计边界。

### 3.2 拒绝：固定公众号风格模板

专业型、故事型或特定作者模板会把不同来源加工成同一种声音，违背来源忠实目标。

### 3.3 采用：来源主导的书面化流程

```text
Transcript + 必要的视频片段
-> 临时来源地图
-> 口语到书面语的最小编辑
-> 载体适配
-> 来源忠实审计
-> Content
```

临时来源地图由 Agent 在工作上下文中维护，不新增持久化产品或 schema。六种业务产品仍然只有 `Profile, Job, Evidence, Transcript, Content, Draft Receipt`。

## 4. 来源地图

开始写作前，Agent 应确认：

- 视频类型，例如调查、访谈、教程、评论或叙事；
- 说话者及其身份、观点和相互关系；
- 原始章节和论证顺序；
- 核心问题、案例、数字、术语和来源自带的比喻；
- 必须保留的限定、反例、异议和不确定性；
- 依赖画面或语气才能理解的时间范围；
- 原作者的专业程度、幽默密度和情绪强度。

Transcript 继续作为唯一文本事实来源。原始 Evidence 和视频片段用于核对说话者、画面指代、强调、转场和高风险歧义，不允许脱离 Transcript 发明文字事实。

## 5. 编辑权限

### 5.1 默认允许

- 修复 OCR、ASR、翻译、标点和断句错误；
- 删除无意义的停顿词、口头填充、明显重复和自我修正；
- 保留有表达作用的重复、节奏和强调；
- 合并破碎语句，拆分过长口语句；
- 把“这里”“这个图”等画面指代改为可独立阅读的明确指代；
- 删除点赞、关注、链接在下方等平台操作语；
- 按原视频已有转场形成自然段和少量小标题；
- 为载体约束做最小标题、摘要和图片位置适配；
- 进行自然语言翻译，但保留原论证、术语和语气。

### 5.2 默认禁止

- 重新选择中心思想或建立新的单线叙事；
- 添加来源不存在的比喻、场景、观点、因果关系和结论；
- 把次要案例提升为标题或全文主线；
- 为了通俗删除专业术语、人物身份、数据来源和限定；
- 合并不同说话者的观点，或把受访者意见写成作者结论；
- 改变原视频章节顺序而不记录必要理由；
- 使用固定公众号腔、特定作者文风或营销式标题；
- 为追求对称而制造等长章节、列表和总结段。

## 6. 载体适配

微信公众号只是承载形式，不是新的作者。默认标题应保留原题或只做不增强主张的最小适配；正文顺序应跟随来源；小标题来自原视频的问题、章节或明显转场；图片只使用原封面和对应论证时刻的时间戳帧。

书面稿不等于逐字稿。应去掉视频平台噪声和口语故障，但读完文章的人应当获得与看完视频相同的信息层次、人物关系、推理顺序和专业感。

## 7. 来源忠实审计

Content audit 除现有事实边界外，还必须检查：

- 每个实质段落能否映射到 Transcript 或 Evidence 时间范围；
- 是否添加了来源没有的比喻、判断或主题；
- 是否改变原视频的论证顺序；
- 是否省略了人物身份、反例、异议或重要限定；
- 是否把相关性升级为因果性，或增强确定程度；
- 标题和摘要是否把次要细节升级成主张；
- 文章的专业程度、幽默和情绪强度是否与来源一致；
- 所有重要压缩、删除或重排是否在审计中说明。

审计是 Agent 工作，不新增硬编码风格评分或新的业务产品。可选的机械检查只能提醒重复标题公式、过多小标题或常见套话，不能替代语义判断。

## 8. Agent 与程序边界

Agent 负责来源地图、语义修复、最小编辑、自然翻译、段落组织、视觉指代和来源忠实审计。程序继续负责 Artifact、哈希、状态、来源、图片约束、schema、验证和外部平台边界。

本次不新增风格引擎、持久化 Style、重写模式 schema 或硬质量分数，也不改变 Content 数据模型。

## 10. 验证

使用现有视频《AI 编程正在毒害你我的健康 | Syntax》做不覆盖原 Content 和微信草稿的本地回归：

- 保留原视频的调查报道结构、人物身份和多方观点；
- 删除口语噪声而非专业内容；
- 不新增主导全文的比喻或观点；
- 对每个实质段落记录 Transcript 时间范围；
- 明确记录省略和压缩；
- 将此前过度通俗化试稿标记为拒绝样例。

仓库文档修改完成后运行规定的 ruff、pytest、MCP、Node、打包和复现检查。`live` 微信操作不在本次范围内。

## 11. 完成标准

- 仓库明确把默认内容转换定义为来源忠实书面化；
- Skill 能区分必要书面编辑与明确授权的深度重写；
- 来源结构、声音、人物、反例和限定进入审计范围；
- 不新增业务产品或风格系统；
- 现有视频回归稿证明文章更接近视频正式文字版；
- 原 Content、Draft Receipt 和微信公众号草稿保持不变。

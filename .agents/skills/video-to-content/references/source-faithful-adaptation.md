# 来源忠实的书面化

默认任务不是替视频创作者重新写一篇文章，而是把已经存在的表达恢复为适合阅读的书面版本。
书面稿可以比逐字稿干净，但不应拥有一个新的作者。

## 开始前：ephemeral source map

Agent 在工作上下文中建立临时来源地图，不保存为新的业务产品：

- 来源类型：调查、访谈、教程、评论、叙事或松散对谈；
- 说话者、人物身份、观点归属和相互关系；
- 原有顺序、章节转场和论证推进；
- 专业术语、数字、案例和来源自带的比喻；
- 反例、异议、限定、不确定性和利益披露；
- 必须结合画面才能理解的时间范围；
- 专业密度、幽默程度、情绪强度和表达节奏。

Transcript 仍是唯一文本事实来源。只有在说话者、画面指代、强调、转场或不确定措辞影响
书面化时，才按时间范围回看原始视频或其他 Evidence。

## 叙述视角：文章不是视频解说

成稿不是“关于视频的解说稿”，而是来源表达换到书面载体后的版本。对单人评论、讲解或叙事，
正文直接采用来源叙述视角，保留有意义的“我”“我们”、反问、讽刺、判断强度和推进方式；对访谈
或多人内容，继续明确谁在说什么，不把所有观点改写成一个旁观者的统一口吻。

来源声明集中在 Content metadata、署名区或一次简短披露中。若一句话只是用“视频认为”“视频指出”
“创作者提到”“本期视频里”把来源原话包装成二手转述，应去掉这层壳，直接表达原有内容。与此同时，
不能全局禁用“视频”或“创作者”：当另一段视频、一次发布行为、作者身份或观点归属本来就是实际
讨论对象时，这些词承担事实或归属作用，必须保留。

将“视频里我们可以看到”“接下来请看画面”等载体操作语改为适合文章的明确指代；若画面本身
构成证据，则在对应段落说明画面展示了什么，并放置经核验的来源帧，而不是假装视觉信息不存在。

## 非实质片段与干净省略

`source_faithful_full` 保留的是实质内容，不是每个 cue。广告、赞助、商品推广、课程或社群导流、
点赞关注投币、评论区互动、链接位置、下期预告和告别等平台 CTA，默认不构成实质章节；Agent 应
记录对应 cue 范围和省略理由，然后从正文中干净移除。同一 cue 同时包含实质收束与 CTA 时，
只删除非实质句子，保留有信息的判断；不能因为 cue 中出现推广或告别词就整条丢弃。

省略后不保留占位标题、括号说明或编辑痕迹，例如“（视频原文中的商品推广段）”“广告已删除”
“以下内容略去”。但如果赞助或利益披露会影响读者判断来源立场，应把必要事实集中保留在来源披露
或相关正文中；如果产品、公司、推广机制本身就是讨论对象，则该段属于实质内容，不能因为带有
推广形式就自动删除。这里同样依赖 Agent 语义判断，不使用关键词一刀切。

## 默认允许的编辑

- 修复 OCR、ASR、翻译、标点、断句和明确的专有名词错误；
- 删除无意义的停顿词、口头填充、重复串场和自我修正；
- 保留有强调、节奏或人物特征作用的重复；
- 合并破碎语句，拆分过长口语句；
- 将“这里”“这个图”“刚才那个”等指代改为可独立阅读的明确表达；
- 删除与主题无关的广告、赞助口播、商品推广、点赞关注和链接位置等平台操作语，并在 audit 中记录省略；
- 按来源已有的章节、问题和明显转场形成自然段与少量小标题；
- 对标题、摘要和图片位置做不增强主张的最小载体适配；
- 做自然翻译，但保留原有术语、论证和语气。

## 逐条字幕不是成稿

来源忠实允许大量保留原作者措辞，但不等于把逐条字幕直接贴进正文。机械拼接 cue、按固定
字符数分段、删除几个填充词或用正则补少量标点，都只是预处理，不能代替 Agent 的书面化。

Agent 至少要实际阅读开头、中部和结尾，并在每个实质章节确认：

- 句子边界已经按语义恢复，而不是按 cue、时间间隔或字符数切分；
- 转写错误、自我修正、无意义口头噪声和孤立应答已处理；
- 长口语句已自然拆分，破碎短句已合理合并，指代可独立阅读；
- 原作者的术语、案例、限定、观点归属和语气没有因整理而丢失。

如果来源本身就是成熟讲稿或出版级文本，成稿与 Transcript 高度重合完全正常；目标不是为了
降低重合率而换词。`raw Transcript passthrough` 只是拦截“高重合、低标点、长段无句界”同时
出现的高风险形态，命中后必须重新书面化，不能仅修改审计字段。

## 默认禁止的改写

除非用户明确要求，不得：

- 重新选择中心思想或把多方调查改成单线观点文；
- 添加来源没有的场景、事实、价值判断、结论或新增比喻；
- 把来源中的次要案例、金句或画面提升为标题和全文主线；
- 改变原有顺序，或为了整齐制造等长章节、列表和总结；
- 删除人物身份、观点归属、反例、异议、专业术语和必要限定；
- 把不同说话者的意见合并成作者立场；
- 将相关性升级为因果性，或把可能、主观感受写成确定事实；
- 套用固定公众号腔、特定作者文风、营销标题或 Agent 惯用总结句。

来源使用了某个比喻，不代表它应成为文章主线。Agent 必须保留其在来源中的权重，而不是因为
它易于传播就将其放大。

## 标题、摘要和小标题

- 默认保留原题，或只做解决长度、语言和上下文问题的最小改动；
- 新标题不得比来源更肯定、更戏剧化或更单一；
- 摘要概括来源实际覆盖范围，不替来源增加结论；
- 小标题来自原有问题、章节或明显转场，不为每一段制造主题句；
- 如果来源没有清晰章节，使用描述性分段，不发明一个来源没有的论证框架。

## 专业性与可读性

通俗易懂不是降低专业密度。首次出现的术语可以用来源已有解释、简短同义说明或必要上下文
帮助阅读，但不要用生活化类比替换准确概念。保留专家姓名、角色、数据方法、限制和不同观点，
让读者能够跟上原本复杂的推理。

## 松散来源

直播、播客或即兴对谈可能没有完整文案。此时可以整理话题簇、删除来回重复并补足明确指代，
但仍应保留实际讨论顺序和观点归属。若需要重构成独立论说文、教程或面向新受众的版本，必须
由用户明确要求，并在审计中记录编辑性重建。

## 来源感知表达复核

完整成稿和章节/图片计划完成后，再读取
[source-aware-expression-audit.md](source-aware-expression-audit.md)。这一步只清理 Agent 新增的标题、
转场、总结和证据边界模板，不重新处理来源作者的真实表达。形式上命中某条规则不等于必须修改；
专业罗列、人物原话、真实对照和来源自带修辞优先保留。

表达复核后必须再次进行下面的来源忠实审计，防止“去 AI 味”成为删除细节、改变语气或重排结构
的借口。

## 来源忠实审计

完成后逐项检查：

1. 每个实质段落能否映射到 Transcript 或 Evidence 时间范围；
2. 是否出现来源没有的新主题、新比喻、新因果或新结论；
3. 是否改变了来源顺序、人物关系或观点权重；
4. 是否为了简洁删除了专业信息、反例或重要限定；
5. 标题和摘要是否把次要细节放大成主张；
6. 语言的专业程度、幽默和情绪是否仍属于原作者；
7. 所有实质省略、压缩、重排和授权改写是否已记录。

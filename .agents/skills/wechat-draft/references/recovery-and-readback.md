# 微信编辑器恢复与回读

当 Browser Bridge、Playwright/evaluate、编辑器入口或保存结果出现超时、空快照、状态不确定时读取本页。
目标是区分“技术操作没有读到”与“草稿业务上没有完成”，并防止重试造成重复草稿。

## 先观察，再重试

1. 不要因为一次 evaluate 超时、DOM 暂时为空或点击没有即时反馈，就判定业务失败。
2. 用可见 DOM/Browser Adapter 快照重读当前页面；必要时对同一读取动作做有界重试。
3. 浏览器按“当前登录状态 + 实际控制能力”选择，不固定 Chrome、内置浏览器或历史标签页。旧标签页输入超时后，先重读；确认失效时才在同一已登录会话中新开 Agent 控制标签页。
4. `setFiles: Not allowed` 是控制能力不足，不是 DOCX 路径问题；复制、改名或换目录不会修复。保持同一登录会话，改用可控文件选择入口；若没有才停在人工边界。
5. 如果入口点击不可靠，可以在当前已登录的可见浏览器会话中打开明确的编辑器入口；不得把 URL 查询参数、
   token、cookie 或浏览器存储写进 Observation、Receipt、日志或项目状态。
6. 一旦页面已经出现候选草稿，先确认目标是否为新建或某个明确的数字 `appmsgid`，再继续写入。
7. 文档导入、文件选择或转换超时后，检查同一编辑器、导入弹窗和正文是否已变化；正文已经出现时禁止再次上传，状态不确定时禁止改用剪贴板覆盖，也不得换一份 DOCX 副本重试。

技术读取失败通常是 `retryable`；真正看到登录页才是 `paused_auth`。不要把登录历史当成当前授权，也不要
把“用户已登录”当成草稿已保存。

## 保存结果不确定时的顺序

1. 先读取当前页面和可能的 `appmsgid`，不要立刻再次点击新建或保存。
2. 如果已有稳定数字 `appmsgid`，刷新或重新打开同一草稿，回读标题、正文、图片、封面、摘要和创作来源。
3. 如果刷新后仍完整存在，有正文图片时才构造 `wechat-editor-observation-v3` 并绑定 Draft Receipt；v3 必须包含天然宽高和显示宽高。
4. 如果没有稳定 ID 或回读不完整，保持当前 Job 未完成并重试同一目标；不要新建第二篇来“试试看”。
5. 只有 Receipt 验证通过后，才可以把 Job 标为 `completed`。Toast、上传完成、编辑器 DOM 或 `appmsgid` 单项
   都不够。

## 必须回读的事实

- 标题与当前 Content 哈希一致；
- 正文开头、中部和结尾完整，图片数量、顺序、可见性、天然尺寸、显示尺寸、画幅和微信托管状态一致，且没有本地路径标记；零尺寸编辑器分隔节点不计入正文图；
- 原视频封面和摘要仍在；
- Profile 要求时，“内容由AI生成”在保存前已选中，并在刷新后的新快照中仍选中；
- 保存模式是草稿，`published=false`；
- 修订使用原数字 `appmsgid`，新 Receipt 通过 `supersedes_receipt_id` 保留历史。

## 禁止的恢复方式

- 不用成功 Toast、上传进度、文章长度或 `appmsgid` 代替刷新回读；
- 不把剪贴板 HTML、图片 CDN URL、token、cookie 或浏览器存储持久化；
- 不因浏览器或文档导入超时就重复上传、叠加剪贴板或创建第二篇草稿；
- 不点击发布、群发、排期、原创或账号管理控件；“内容由AI生成”是创作来源披露，不是原创声明。
